# macOS Event-Tap Lifecycle

Use this skill for native macOS `CGEvent` tap, `CFMachPort`, `CFRunLoop`, Accessibility, and callback/run-loop ownership work. It is for topology and lifecycle changes that must preserve an existing input policy, delivery contract, and downstream behavior.

## Non-negotiables

- Give the event tap, mach port, run-loop source, callback context, and final resource release one explicit owner thread. A lock around MainActor-owned framework resources is not an ownership transfer.
- Keep the framework callback synchronous and bounded: parse, read typed eligibility, admit or pass through, pair key events, record, signal, and return. Never await, hop to MainActor, call UI/permission/hardware APIs, or wait for downstream capacity from the callback.
- Use a bounded signal as a wake-up only. Keep capacity, FIFO order, overflow, pairing, and stale-session rules in the existing Domain gate; do not introduce a second delivery queue in Handler.
- Treat lifecycle generations as capabilities. Capture the lifecycle and polling/revalidation generation before an `await`; re-check both and the current phase after it. A stale result is discarded, never converted into a new failure or suspension.
- Close admission before cleanup, release the old owner before reopening, and make repeated stop/release requests converge without duplicate release notifications.
- Keep shared locks narrow. Protect only handoff state, commands, waiters, and framework handles; release the lock before CoreGraphics/CoreFoundation, Accessibility, UI, Service, or run-loop calls. Snapshot diagnostic state under the lock, then emit logs outside it because logging can block a callback.
- Keep semantic reason conversions in one boundary mapping. Reuse it from lifecycle adapters instead of duplicating exhaustive switches that can drift when a new reason is added.
- Use checked continuations or an owner-run-loop command source for asynchronous start/stop handoff. Never join the callback or MainActor, and never use a semaphore to make teardown synchronous.
- Make process termination non-blocking and single-shot. Use AppKit's deferred termination reply, let cleanup win when it completes, and provide a bounded fallback that can reply without claiming native teardown completed.
- When a failed permission open latches suspension, do not treat a later permission grant as an implicit reopen; only the contract's explicit reopen path may clear the latch, or a stale callback can revive an owner that has already been torn down.
- Test at allowed Domain/Service seams and preserve the common offline contract. A Release offline pass proves modeled policy and Service behavior, not native callback scheduling, tap lifetime, Accessibility, OSD, or physical hardware behavior.

## Procedure

1. **Freeze the behavior surface.** Record the existing parser/filter, tap options and event mask, admission capacity, ordering, overflow behavior, key-up pairing, lifecycle contract, consumer, instrumentation, and Service calls. During a topology experiment, change ownership and scheduling—not workload or policy.
2. **Trace the caller-to-effect path.** Identify the app lifecycle entry points, permission polling, sleep/wake/reopen paths, callback context, Domain gate, MainActor consumer, OSD, and Service. Search every caller before changing a signature or deleting a legacy router. After centralizing a suspension or diagnostic boundary, search every Handler, lifecycle adapter, owner, and callback context for direct calls to the Domain mutator and require them to route through that boundary; a conformance feed can exercise one duplicate while a second copy survives only on the native path.
3. **Sketch the ownership boundary.** Put all CoreGraphics/CoreFoundation resource fields on the owner thread. Expose only Sendable value results and asynchronous commands to the MainActor adapter. Keep the callback context independent of MainActor objects.
4. **Build the bridge.** Add a private owner-run-loop source that drains commands outside the lock. Use a bounded `AsyncStream` or equivalent only to coalesce wake notifications; the consumer must drain the Domain gate, not receive commands from the stream itself.
5. **Fence every await.** Distinguish `stale`, `enabled`, `disabled`, and `unavailable` outcomes where a status can race a lifecycle change. Keep lifecycle freshness in the Domain's stamped result, but keep poll/revalidation identity in a Handler-owned token when it is coordinator state; do not push Handler booleans or poller ownership into Domain merely to unit-test it. Check both identities before applying the observed result: a post-`await` guard in the coordinator is too late if the awaited interceptor already suspended or tore down state. Return a typed observation for the coordinator to fence and apply, or pass a currentness predicate into the async adapter and evaluate it immediately after the await, before any mutation. Unit-test Domain generation rules and prove the composite Handler fence through the candidate-bound conformance executable, not Handler unit tests. Re-check current phase before stopping polling, suspending, publishing, presenting, or submitting.
6. **Implement lifecycle ordering.** Sleep increments the generation, rejects new admission, discards queued work, and then requests owner teardown. Wake waits for teardown and requests fresh validation only for a lifecycle that slept active. An unavailable or suspended wake remains outside eligibility until an explicit reopen. Reopen cannot create a replacement while the previous owner is still active.
7. **Harden failure and termination paths.** Make owner teardown idempotent and perform the actual tap release on its owner thread. Model owner-thread readiness with typed `ready`, `failed`, and `stale` outcomes rather than a Boolean: a genuine run-loop/source startup failure must latch the owning creation-failure policy, while a concurrent stop or teardown race must remain stale and inert. Audit every path returning a public `.failed` result so the underlying failure is either handled at its owning boundary or carried explicitly to the caller; do not rely on one lower-level failure path to cover sibling exits. Ensure an unexpected run-loop exit tears down remaining resources. For termination, guard the AppKit reply with a thread-safe single-shot gate; emit completion diagnostics only when cleanup actually wins, not on fallback.
8. **Add seam proofs.** Cover bounded capacity and FIFO order, overflow pass-through and suspension, stale pre-presentation delivery, sleep/suspension/wake, key-up pairing until owner release, lifecycle-plus-poller fencing, and any centralized mapping. Do not force Handler/CoreGraphics unit tests through mocks when the test scope excludes that boundary. For competing implementations, use an opt-in Release executable that compiles each candidate's real bridge sources and enters through the real post-parse candidate seam; retire any common harness that drives only shared Domain/Service code because it erases the scheduling variable being compared. Keep framework-free scenario and workload files byte-identical, confine topology adaptation to candidate-local bindings, and emit topology labels only after identities are actually observed inside the owner-thread command/run-loop seam—hard-coded names are not proof. Freeze production-equivalent admission capacity and label normal-use, stress, held-consumer, lifecycle, and cleanup phases explicitly. Never compare absolute monotonic ticks produced by different processes or runtime APIs merely because both claim monotonic/system-uptime semantics—their epochs and conversion behavior may differ. For cross-process phase attribution, stream child boundary identities and child-local timestamps, stamp each complete boundary record when the parent observes it, and attribute parent resource samples only on that parent clock. Keep the executable's diagnostics useful, but make the outer runner independently compare its correctness output with a spec-derived literal matrix so the artifact cannot self-grade.
9. **Gate the measurement apparatus before collection.** Separate `gate`, same-candidate `control`, and cross-candidate collection so A/B ranking cannot run while correctness or evidence integrity is unresolved. A single-candidate gate must bind the immutable candidate ref, exact dirty-worktree source closure, shared-driver digest, frozen configuration, compiler flags, executable path, and executable hash. Retain every resource poll as sampled, failed, or censored; preserve child boundaries and their parent-observed timestamps; and require every total and per-phase summary to reconstruct from raw records. Reject a nominally populated phase with zero attributed samples instead of accepting an empty reconstruction, because validator and summarizer can otherwise agree on the same broken clock assumption. Parse an append-only boundary sidecar only through its last newline and retry an incomplete tail on the next poll so a concurrent partial write cannot corrupt the gate. Materialize every native proof limit as an explicit machine-readable report entry—not only as ADR prose—including callback scheduling/timeouts, Accessibility identity/prompts, AppKit rendering/scanout, ordinary-input effects/restoration, physical hardware, installed-process resources, and unavailable native counters. Validate the exact list against a separate spec-derived literal so omissions fail the gate. In mutation tests, deep-copy mutable oracle collections into fixtures before removing or changing entries; aliasing the fixture to the oracle lets both mutate together and produces a false pass. Keep run ordinal out of the configuration digest so repeated controls share one configuration while retaining the ordinal as run metadata. Before declaring controls green, run a correctness gate for every candidate × workload × instrumentation cell; a repeatability manifest can be internally valid while leaving a candidate/workload combination unexercised, so it cannot substitute for full matrix coverage. Compare A/A and B/B behavior fingerprints with timestamps and resource noise excluded, then permit A/B collection only after both controls are green. Before the first cross-candidate observation, freeze a machine-readable protocol that names the exact build and source bindings, workloads, instrumentation modes, warmups, run counts, counterbalanced order, per-run sample minima, sample and summary definitions, missing-data replacements, equivalence and selection rules, environment invariants, observation sources, retention, and stop conditions. For every accounting field, predeclare whether it is a within-run conservation invariant, a cross-candidate equality gate, or a ranked outcome; for ranked outcomes define direction, equivalence, and interaction with candidate selection. Otherwise an analyzer can silently turn a genuine topology difference into an invented correctness failure after collection. Require every declared exact accounting metric to exist in each phase report, and validate conservation identities such as attempted = admitted + rejected and admitted = completed + discarded + pending. Define each identity over one event universe: when attempted counts key-down admission attempts, rejected counts only rejected key-down admissions; unmatched key-up pass-through belongs to pairing behavior and must not inflate admission rejection. Exercise that distinction in a Domain regression test and in a stress phase that can overflow before later key-ups; a protocol that mixes event classes or names rejected/discarded work without a report field leaves the result irreconstructible. Define a robust repeatability statistic together with the exact minimum valid runs and adjacent differences it consumes; a small-sample nearest-rank p95 can collapse to the maximum and silently inflate an equivalence band. Bind the protocol digest into the configuration digest, report, and binding manifest, retain the exact protocol file beside the evidence, and validate/materialize the complete schedule with a read-only tool; a Boolean claiming digest binding is not proof, prose leaves post-result choices open, and a runner that can collect during protocol validation breaks the pre-observation boundary. Pin every executable tool and expected-matrix digest before preparation and re-check them immediately before and after each run; a long campaign otherwise permits later cells to execute different bytes under one state-level binding. Before analysis, revalidate each selected report against its recorded digest, candidate/configuration identity, source and tool bindings, child status, literal scenario/topology contract, raw reconstruction, and behavior fingerprint; validating only campaign-state digests lets a changed or invalid retained report silently influence the result.
10. **Run real verification.** Build and test with the repository's commands, run the candidate-bound Release gates and same-candidate controls, inspect raw samples, reconstructed summaries, reports, and executable/source/protocol bindings, then run `git diff --check`. Interpret a collector's nonzero exit only after reading stderr, campaign state, and analysis: a complete frozen campaign may deliberately return nonzero for a predeclared `inconclusive` outcome. In that case preserve the evidence, rerun analysis against the retained reports to prove reproducibility, and do not tune the workload, equality rules, or selection policy after seeing the result. Give every subprocess layer its own protocol-owned watchdog and regression proof. Run each outer command in a newly owned process group; keep nested candidate children in that group so an outer timeout covers the apparatus and its descendants, while the inner watchdog still terminates and kills the direct candidate. Terminate the owned group, wait the frozen grace period, then kill surviving descendants; killing only the direct child can orphan compiler jobs or a candidate hidden behind a wedged apparatus. Drive the inner watchdog with a harmless sleeper that emits both output streams and ignores `SIGTERM`, then assert escalation to kill, process reaping, retained stdout/stderr, censored samples, and timeout metadata. Separately drive the outer watchdog with a harmless parent that leaves a descendant behind, assert that no non-zombie process survives, and assert timeout conversion into the runner's typed/domain error. After any byte change to a bound runner, matrix, protocol, driver, or candidate source, create fresh gate evidence and rerun affected controls before review; old evidence can remain valid historically but cannot prove the new fixed point. Evidence output directories must be caller-selected, new, and never cleared; preserve failed and superseded directories rather than silently reusing them. When a source-bound probe accepts only Git revisions but the implementation is dirty, use `git stash create` to obtain a dangling snapshot without moving refs or changing the worktree, and only when every required source is already tracked; otherwise make the probe consume and hash exact worktree files. State native proof gaps explicitly instead of promoting modeled measurements to callback, Accessibility, OSD, hardware, or installed-app claims.

## Failure patterns

- **Startup/stale conflation:** a Boolean owner-readiness result makes run-loop/source startup failure indistinguishable from a concurrent stop. Return typed `ready`/`failed`/`stale`; latch only the genuine startup failure and leave the stale race inert.
- **Stale-poller mutation:** an old permission/status poll suspends, tears down, or calls `stopPermissionPolling()` after a new poller started; compare the polling token as well as lifecycle generation before the awaited result reaches any mutating method. A coordinator guard after a mutating async call cannot undo stale damage.
- **Callback coupling:** a callback retains or invokes a MainActor adapter; pass a Sendable callback context instead.
- **Lock leakage:** a mutex remains held while calling framework, UI, permission, Service, run-loop, or logging APIs; snapshot state, unlock, then emit.
- **Duplicated semantic mapping:** the same suspension-to-diagnostic switch appears in multiple adapters; centralize the conversion so new cases cannot drift.
- **Ambiguous release:** both the consumer and owner finish the wake stream or clear tap ownership; choose one owner and make the operation idempotent.
- **Proxy proof:** an offline harness or successful compile is reported as native tap, callback, Accessibility, OSD, or hardware proof.
- **Cross-process clock conflation:** parent resource samples and child phase timestamps are compared as absolute nanoseconds without a proven shared epoch; observe child boundary records on the parent's clock (or calibrate explicitly) and require nonempty phase attribution, because reconstructing with the same invalid comparison is tautological.
- **Unproven escape hatch:** `@unchecked Sendable` is added without an explicit confinement invariant and complete lock coverage; the annotation must describe a proven owner, not silence strict concurrency.
- **Nested-watchdog orphan:** the outer runner kills only its direct apparatus child while the candidate or compiler descendants live in another group; make the outer command own the complete inherited process group and prove descendant cleanup.
- **State-only evidence validation:** analysis trusts report paths after checking only campaign-level tool digests; bind each report by digest and re-run its correctness, reconstruction, and artifact checks before computing metrics.
